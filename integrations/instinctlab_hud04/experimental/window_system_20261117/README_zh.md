## 以后生成动作的归档规则已实现

`motion_archive.py` 提供 `freeze_file()`：

1. 每个版本按内容 SHA256 保存，不重复使用“最新动作”文件名覆盖旧版本。
2. 同时记录原始动作哈希、目标模型哈希、明确输出角色及保守验收状态。
3. 写后重新读取 NPZ 和 JSON；不同版本不覆盖，同 hash 内容/元数据冲突直接拒绝，符号链接拒绝。
4. 只承认 local-same-sandbox，不伪称远端同步成功。

本次把既有关节求解 runner 的成功路径接入归档：**结果文件写出并校验后，必须成功创建并验证第二份内容寻址副本，才生成成功报告/向父进程发成功消息。** 此路径有语法/AST 接线测试，归档器本身有 8 项运行测试；没有为了验证接线重复运行真实 LP。旧 intent 仍会阻止盲目重跑。

后续其他候选写出器也须显式调用该归档器，不能声称它自动拦截任意脚本的全部文件写入。远端发布仍需单独核验 GitHub/私有存储的实际读回结果。
