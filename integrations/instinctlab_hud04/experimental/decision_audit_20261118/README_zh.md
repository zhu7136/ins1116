# HUD04：明确当前工作意义，再继续推进

## 任务定位

最终目标不是让HUD04的关节曲线看起来像G1，而是替换InstinctLab中的机器人后，训练并验证HUD04完成原地形感知任务。头yaw/pitch固定0，不进入29身体动作；保留原数据、997帧、90Hz和模型限值，不裁剪角度、不伪造参考验收。

当前处于**生成可信HUD04参考动作**的中间阶段，尚未进入最终策略训练。已有完整997帧关节方向诊断，只解决“身体骨段大致指向哪里、关节是否守限”，并不解决机器人在世界中放在哪里、手足哪一面接触、能否真正承重/避碰。一个不超限但手掌或足底翻转的轨迹，同样不能作为已验收任务示范。

## 本轮先查清的问题与实测结论

### 1. 87.83°尾部和中段回退是否证明目标不可达？不是。

读取并核对上轮不可变997帧文件SHA256 `2aa620d3086ed5f1c260c210e38fcb3d3a94cbaea549911844b8e4c31127ddc0`。在右臂风险段244–345的102帧和中段480–510的31帧，执行7,192次**互相独立、不会累加的数值扰动评估**，没有调用优化器或生成新轨迹。

每次只对某帧某关节选取不超过.01rad的可行扰动，使用原模型位置限值及两侧原生相邻帧速度界，保持原来L1方向误差+.001*相对原始seed偏移的同一目标。

- **133/133帧都仍存在可行的目标下降扰动**。这直接反驳“上轮已经收敛”，但不证明最终可以满足完整任务，也不证明解剖/接触对应正确。
- 第257帧右肘-0.01rad，在两个相邻速度边和关节限位均合法时，右前臂误差87.825957°→87.253210°；该例由独立旧RobotTree FK重算确认。只是一个反事实证据，不是保存或应用的新动作。
- 上轮84次更新全部触及.15rad信赖域边界，最后一次仍有3.8011目标下降。固定预算完成不是收敛证书。

### 2. 只继续降低方向误差能否解决手足技能？不能。

在997帧计算目标方向Jacobian，24*29矩阵的数值秩始终16（1e-8阈值），每帧至少13维线性化零空间。10个具名列完全为零：双腕的yaw/pitch/roll共6列、双踝pitch/roll共4列。另用独立旧FK在3个位形对10列作30次数值变化检查，方向变化确为0。

这符合使用first-wrist-pivot及ankle-pitch枢轴的构造：那些骨段方向根本看不见腕转和足底转动。seed正则可以保留一些数值，但不能证明掌/足底任务姿态正确。不能将“方向平均误差继续下降”当成参考验收或感知技能进展的替代指标。

## 下一步的实际顺序与完成标准

1. **任务相关的对应/标定先行**：沿用正确G1 popsicle模型和官方源消费接口证据；逐项绑定源根/四元数/单位/世界Terrain条件，明确源/目标躯干与手足末端的旋转偏置和掌/足/膝材料点。不得用最小穿透选坐标，不把腕枢轴当掌面，不把“近地”自动当支撑。
2. **有界联合重定向**：标定通过或明确声明条件后，将根6维+29关节与方向、躯干/手足姿态、材料点跟踪接入已有35维窗口系统；同时处理实际裁剪Terrain/侧壁和自碰撞。对支撑候选分阶段审查，不硬锁整段右腕近地帧。收敛报告同时保留最差/分段误差、原始关节/速度限值及是否改变任务语义，不能只报平均数。
3. **独立动作和环境门禁**：世界位姿、原生全997帧、限位/速度、地形/自碰撞、手足膝支撑与无滑动等逐项复核；还需解决此前真实运行时退出/重置/任务/深度/干净退出门禁。优化“可行”不是动态可执行证明。
4. **再做短时动态/跟踪验证，最后感知策略训练**：GPU前实时查询账户+项目服务器状态并查重。已知任务不重交；短GPU权限保留，但不直接开始长PPO，不无限试预算。

因此，下一优先级由“继续只压方向平均误差”调整为**补齐有任务含义的姿态/接触对应，再做有界联合求解**。133帧审计已证明仍有数值下降空间，后续不必靠反复单纯方向试跑来证明这一点。
